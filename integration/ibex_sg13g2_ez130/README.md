# Ibex / SG13G2 / EZ130 verification inputs

`prepare.py` creates a fresh, locked benchmark directory from an already checked
out pinned Ibex source and the installed PDKs. It verifies the source revisions
and EZ130 TT identity, records the converter and output hashes, and refuses a
nonempty output directory. `config.json.in` and `constraints.sdc` retain the
concrete setup used here. Preparation is not physical qualification.

```sh
systemd-run --user --scope -p MemoryMax=2G -p MemorySwapMax=0 timeout 240s \
  python3 integration/ibex_sg13g2_ez130/prepare.py \
  --workspace .work/ibex-new --base-rev empty \
  --ibex-source /path/to/pinned-ibex --gnu-time /path/to/gnu-time
```

The local reproduction test regenerated byte-identical converted RTL in 3.92 s
with 284,036 KiB peak RSS. Its nonempty-directory control failed with
REVISION_CONFLICT and left the configuration unchanged. Run the resulting
external flow under the scale lock with an 8 GiB memory / 2 GiB swap scope and
an explicit deadline. The current template requests 16 router workers and
disables detailed-router snapshots; all retained report and artifact I/O counts
toward wall time. Both final benchmark samples must use the same 16 distinct
physical cores. The native worker binds those CPUs in the cgroup as well as the
producer, so detached children cannot enlarge their allocation.

These inputs accompany the local campaign in `.work/ibex-sg13g2-ez130/`.
The public `./rusteda flow` entrypoint now accepts the explicit
`ihp_sg13g2_ez130` native producer contract. Fresh public run16 (2026-10-30)
completed all sixteen native gates from the original RTL. The matched LibreLane
comparison is recorded separately. An application/protocol test pass does not
establish EDA correctness.

- `ibex_sram_bench.sv`: Ibex v2.1.0 at
  `38c070939183cc10940b66c8e9e04eeca6b65470`, default RV32IMC configuration,
  with two actual IHP `RM_IHPSG13_1P_1024x32_c2_bm_bist` SRAMs.
- `tb.sv`: bank isolation, first/last address, byte-write mask and executed
  load/add/store smoke tests against the vendor functional models.
- `macro_contract.py`: bounded structural checking of the public mapped
  Yosys JSON. A successful synthesis exit code is insufficient: both macros,
  their signal widths, clocks, byte masks and inactive BIST must survive.
  Powered netlists also check VDD!, VDDARRAY! and VSS! connections. This
  checker is not a formal equivalence oracle.
- `pdn.tcl`: explicit EZ130 Metal1 rails and IHP SRAM Metal4 supply collection
  on Metal5, connected to the global TopMetal1/TopMetal2 grid. The original
  SRAM has no top-metal supply pins; a default top-metal macro hook leaves
  it unpowered. This configuration requires matching placement/technology
  and independent DRC/LVS; a power connectivity pass alone is insufficient.

The original PDKs and libraries are required, without edits: IHP SG13G2 v0.3.0
at `5cccb161f7492697cfa52eb14dc03beb00bdca9e`, and ETH EZ130 8T v1.1.
Use EZ130's `ez130_sg13g2_tech.lef`, not the stock standard-cell technology LEF.
The campaign uses common TT 1.20 V/25 C and SS 1.08 V/125 C; the supplied fast
SRAM and standard-cell temperatures differ and are not silently conflated.

The v0.3.0 KLayout deck incorrectly checks the manufacturing grid on SRAM pin
annotations. IHP fixed this in
[PR #1025](https://github.com/IHP-GmbH/IHP-Open-PDK/pull/1025), commit
`a6a7e6ccf95b480f786039890b40670db6a54419`. `prepare_signoff_deck.py` copies the
original KLayout collateral into a new locked workspace and replaces exactly
that one file with its hash-checked upstream version. It preserves the SRAM GDS,
all manufacturing-layer grid checks, and the old deck for comparison. Do not
set `no_offgrid=true` to hide the annotation errors.

```sh
python3 integration/ibex_sg13g2_ez130/prepare_signoff_deck.py \
  --pdk-source /path/to/IHP-Open-PDK \
  --workspace .work/ibex-signoff --base-rev empty
```

The official fix commit must already be available in the PDK Git database. The
copy is bounded to 4096 files / 256 MiB and hashes files incrementally (estimated
peak memory below 64 MiB). The real preparation measured 20,712 KiB RSS; a
nonempty-workspace control is rejected without changing provenance. A separate
KLayout control still rejects an off-grid Metal1 manufacturing rectangle while
accepting its on-grid counterpart. These controls validate the deck preparation,
not the Ibex layout itself. Both benchmark flows must use the same prepared deck.

Peak-memory estimate before these fixtures/checks: the two memories are opaque
macros during synthesis, while the smoke simulation stores 2 x 1024 x 32 bits.
The macro checker bounds input to 64 MiB and cells to 100,000; decoded JSON is
estimated below 1 GiB, scalar buffer traversal is limited to 64 hops with cycle
rejection. The complete flow has a separate 8 GiB cgroup/2 GiB swap and wall guard,
an explicit worker limit and the root scale lock. The initial controls use two
physical cores; full repair verification uses sixteen, with a separate memory
estimate. See the local `BUDGET.md`, GNU-time logs and cgroup observations.

Run the checker under a resource guard with a supplied mapped JSON:

```sh
systemd-run --user --scope -p MemoryMax=1G -p MemorySwapMax=0 \
  timeout 30s python3 integration/ibex_sg13g2_ez130/macro_contract.py mapped.json
```

Validation uses actual vendor-model simulations plus negative controls made
from the real reference netlist. Removing a macro and enabling BIST are
rejected. The actual native empty-blackbox result loses both SRAMs and is
independently rejected by the simulation's first memory readback. Do not use
that invalid netlist's runtime or area as a benchmark result.

The fresh native recipe is composed by `native_frontend.py`, `native_backend.py`
and `native_flow.py`: original RTL, newly derived ECO plans, one final CTS,
all-signal routing, real SRAM GDS, native/OpenRCX nominal extraction, independent
logic/vendor simulation, complete foundry main/antenna DRC, full-device LVS and
TT/SS extracted setup/hold/DRV. `qualify_native.py` binds all sixteen gates to
the actual run's final hashes. Generation requires qualified exact binaries and
real dual-baseline/negative-control evidence; missing qualification is an error.
Do not create a placeholder qualification or import historical pass reports.

These files are the helper set of public run16, ported from the run's own
`helpers/` directory (`integration-port-run16.json`). run16 completed all sixteen
gates with RustROAD engine v24 (commit `0813571`); older engines leave the
SRAM-band supply rails floating and fail main DRC and LVS. One shared file has
changed since: `signoff_timing.py` now looks up a top-level port's net by name,
because OpenSTA's `get_nets -of_objects` rejects ports. run16 reported no
unannotated port, so the change does not affect its result.

- **Floorplan.** `contract.json`, `config.json.in` and `native-floorplan.json`
  describe a 1100 × 1000 µm die with both SRAMs at y = 631.3 µm.
  `native-physical.json` adds one placement blockage over the mouth of the
  inter-macro channel. The same contract drives the LibreLane reference.
- **Pin plan.** Before the first ECO round, `native_frontend.py` places the design
  once and runs `native_frontend_inputs.py pins`. Each signal pin goes to the core
  side nearest its load centroid, at an along-side target (RustROAD
  `IoPlan.targets`). Round-robin pins put clk_i and rst_ni at die corners.
- **Port DRV.** RustSTA's DRV report does not check input-port driving cells
  against max capacitance, so `native_ecos.py` checks port nets itself with the
  same margin and wire estimate as internal nets.
- **Clock balance.** `native_ecos.py` (`electrical.clock_balance`) adds DLY1X2
  stages to the ungated launch registers so that they match the gated clock tree.
  This replaces long hold-fix chains.
- **Post-route repair.** Antenna repair, its verifier and the one full native
  extraction run on the trial route (`be_antenna_repair`, `be_antenna_verify`,
  `be_extract`). `native_postroute.py` (step `be_postroute`) then runs RustSTA
  at TT and SS on that SPEF, bound to the workspace path, the HEAD revision's
  bytes and the exact extraction arguments; it does not extract again. Drivers
  near a capacitance or transition limit get an equal-width upsize. The step
  then replays the frontend's final import/place/CTS exactly and routes with
  `--prior-workspace` (the screened route), so unchanged nets keep their
  geometry; each rebuild is antenna-repaired, verified and extracted again with
  the same pinned helpers and arguments, then screened again. If nothing needs
  a resize, the final workspace is the screened trial, hard-linked file for
  file, and `backend/native.nom.spef` is a hard link of the trial SPEF. The
  earlier order, in which `be_postroute` extracts the pre-antenna trial itself
  and `be_extract` extracts the final layout again, remains available as
  `native_backend.py` `postroute_order: extract_before_antenna`; the
  foundry-first capture protocol requires it.
- **Native backend steps.** `native_backend.py` `backend_steps: native`
  composes `be_profiles`, `be_antenna_repair`, `be_antenna_verify` and
  `be_postroute` as commands of the pinned `rustroad` (`physical-inputs`,
  `antenna-session`, `verify-antenna-lineage`, `postroute-repair`; RustROAD
  `docs/flow-steps.md`) and pins none of the Python helpers
  (`native_physical_inputs.py`, the RC-profile builder, the frozen
  `antenna_session` scripts, `native_postroute.py`). The step ids, their
  order, their output paths and the files they write are unchanged; the input
  documents lose their Python pins (`rusteda.native-physical-inputs.v2`,
  `rusteda.antenna-v3-independent-verifier-inputs.v2`,
  `rusteda.native-postroute-inputs.v3`). It needs the screen order and the
  grouped single-process antenna session. The default stays `python`: the
  qualification composer (`native_flow.py`) and `qualify_native.py` bind the
  Python helpers by path and hash and refuse a native-step fragment, and the
  foundry-first protocol is bound to the earlier order. The host benchmark
  composer (`integration/ibex_host_benchmark/compose_native.py`) selects
  `native`.
- **Composition and qualification.** `native_flow.py` checks either order; in
  the default one, verified antenna repair and the extraction precede
  `be_postroute`, which precedes every final export. `qualify_native.py` binds
  its lineage and reads the expected SRAM placement from the pinned contract.

run16's RustSTA/OpenSTA same-SPEF difference is 0.806 ps against the unchanged
1 ps gate. The gap is effective-capacitance modelling on RC-heavy nets, so a
longer clock-gate enable or clock-port net can cross it. A clock-only antenna repair returns explicit subset status;
the complete original Ant.a..i deck on the final all-signal GDS is mandatory.
Resumed LibreLane attempts and local route replays remain repair diagnostics.

## Host reproduction · 2026-11-02

[`../ibex_host_benchmark`](../ibex_host_benchmark/README.md) reran this recipe on
a 4-vCPU cloud host that had none of the first campaign host's local artifacts
(cgroup v1, no swap, no systemd user manager), next to LibreLane 3.0.17's
Classic flow from the same prepared inputs, and applied the same gate scripts
to both final layouts. The host needed these deviations; the harness README
lists each edit:

- **EZ130 collateral.** 5 of the 7 EZ130 files that `contract.json` pins are
  byte-identical; all IHP and SRAM collateral matches. The SG13G2 tech LEF and the cell GDS are reconstructed from
  public sources and differ from the pinned files, so a host copy of
  `contract.json` pins the reconstructed hashes; with the repository copy,
  `prepare.py` stops at its collateral identity check.
- **Tools.** nixpkgs builds (OpenROAD 26Q3, OpenSTA 3.1.0, Yosys 0.70, KLayout
  0.30.12, Magic 8.3.689, Netgen 1.5.325) replace the LibreLane devshell
  AppImage. The converted RTL is `da905268…` instead of `8a8fe84b…`.
- **Composition.** `compose_native.py` writes the composer inputs and stops at
  the backend prefix manifest. The component-qualification evidence that
  `native_flow.py` and `qualify_native.py` require is not published and was not
  fabricated, so the run is `unqualified`.
- **Hardware.** 4 vCPUs instead of 16 logical CPUs of an i9-13900HX. Routing
  uses 4 threads instead of the template's 16 router workers; native extraction
  and GDS export pass no `--threads` and run on RustROAD's default 2-thread
  pool. This run does not meet the 16-core requirement above.
- **Helper patches.** Host-local copies accept 4 threads, read the cgroup-v1
  memory controller, accept the host executor's owned memory cgroup instead of
  a systemd user scope (LVS helper), pass the RC calibration rules path
  explicitly and parse LibreLane's DEF in the density gate.
- **Antenna repair.** The grouped single-process session in `antenna_session/`
  replaces the legacy path, whose complete antenna report for this layout
  exceeded RustROAD's 128 MiB report cap.
- **LibreLane.** Classic flow with `DRT_THREADS=4`, without the
  `reference_flow.py` repair loop of the
  [matched LibreLane reference](#matched-librelane-reference); LibreLane's own
  post-GRT design repair is enabled instead (`RUN_POST_GRT_DESIGN_REPAIR=true`).

With these deviations the repository recipe reproduces run16-class QoR
(run16 values from the [2026-10-30 receipt](../../docs/benchmarks/ibex-sg13g2-ez130.json)):
233,909.2 µm² standard-cell area and 33.25 % final non-filler density (run16:
233,909.222 µm², 33.2521 %), 1,679,076.6 µm of routed signal wire (run16:
1,678,598.6 µm) and 301,099 vias (run16: 301,859). The layout passes every
design gate on the shared scripts. The producer stops at `timing_accuracy`:
RustSTA and OpenSTA differ by 1.4052 ps in TT setup worst slack on identical
native SPEF, against the 1 ps gate (run16's largest difference: 0.806 ps). GDS, DEF, all netlists and the native SPEF were
byte-identical across two complete native runs on the host. The run does not
reach R20/R21's QoR; those recipe inputs are not in the repository
([campaign note](campaigns/early-20261101/README.md)).

## Physical-QoR and runtime settings · 2026-11-04

`native-physical.json`, `native-routing.json`, the repair policy in
[`../ibex_host_benchmark/compose_native.py`](../ibex_host_benchmark/compose_native.py)
and the frontend and backend composers carry the settings below. They need
RustROAD `0bbf81c` or later (electrostatic placement, the staggered tap
lattice, seeded clock-tree re-placement, the track router's quality controls
with post-route via reduction and strict wide-metal cycle cuts, and the
`export-gds` shape and via styles), RustSTA `3550739` (`ruststa run
--concurrent-corners`) built against RustEDA-Common `6668eec` (`rusteda import
--lib-cache`), and RustSys `86e59d8`. Older builds reject
`clock.seed_from_placement`, `tap.pattern.unpaired`, `track_router.qor`, the
`export-gds` options `--merge-shapes` and `--vias` and the two STA options as
unknown, so these files and the module pins change together.

- **Placement.** `cell_spacing_sites` 2 (was 7, i.e. 2.94 µm between cells) and
  the electrostatic global placer (`placer.electrostatic`: target density 0.6,
  at most 200 iterations, 512 evaluations and 4 backtracks, 2 workers,
  spacing-aware density). Its result does not depend on the worker count (a
  unit test covers 1 to 5 workers; the Ibex placement is identical at 1, 2
  and 3).
- **Taps.** `tap.max_gap` 42 µm on a staggered lattice (phase 21 µm) with extra
  taps on unpaired `cell_top` row edges: 5,934 taps instead of 13,923.
  `contract.json` declares the same 42 µm (`native_tap_max_gap_um`), and
  `qualify_native.py` pins that contract by hash (`CONTRACT_SHA256`), so the
  file and the pin change together (`tests/test_recipe_pins.py`). The
  foundry-first joint tap proof pins its own original T1 contract (30 µm,
  `TAP_CONTRACT_SHA256`, frozen as `tests/fixtures/foundry_first_t1`) and the
  T1 30 µm lattice; it rejects this recipe's contract and lattice, so it
  remains a proof of the T1 configuration only.
  `native_frontend_inputs.py` admits only the three lattices that have
  latch-up evidence on this floorplan: 15 µm aligned, 28.98 µm staggered by
  14.49 µm, and this one. Without the `cell_top` taps the 42 µm lattice leaves
  LU.a boxes uncovered, so the margin is load-bearing. The foundry main deck
  (shared `drc` gate) checks LU.b only; the shared `latchup` gate
  (`tap_coverage_runner.py`, LU.a and LU.b, 20 µm, conservative box
  certificate; in a non-rectangular n-well LU.a also needs a path inside the
  well, as the foundry rule grows the ties inside NWell) checks both on every
  final GDS and fails on any box it cannot prove. The maximal foundry deck (`signoff_latchup.py`, which includes LU.a)
  is not part of the flow; it passed on the GDS of the first runs below. Both
  checks fail on a copy of a final GDS with the taps of one 100 µm window
  removed.
- **Clock tree.** `clock.seed_from_placement`: the CTS re-placement starts from
  the current placement.
- **Routing.** Metal2 pin access, `via_cost` 2520, `wrong_way_factor` 3,
  `heuristic_weight` 2 and `track_router.qor` (`prim_order`, `drop_portals`,
  `net_aware_access`, `small_net_terminals` 10, `small_net_weight` 1,
  `notch_bridge`, `strict_wide_cycles`, `via_reduction`, `dedupe_vias`,
  `straighten`). Metal2 access needs `notch_bridge`. With vias priced
  higher (2520 instead of 1680) and wrong-way steps lower (3 instead of 4),
  a short wrong-way Metal2 jog often costs less than a pair of vias. Such
  jogs can close small loops through a pin's own escape that cleanup fills
  into wide metal; `strict_wide_cycles`
  cuts them (without it, routing the placement of the RustSys published on
  2026-11-02 ends with an unresolved wide-metal pair). `via_reduction`
  re-routes, after repair, every net with at most 10 terminals and at most
  20 µm of routed wire per connection against the fixed metal of all others,
  with vias at twice their price (5,040 DBU) and an admissible search capped
  at 10,000 expansions per net, and keeps a route only when it removes vias
  for at most 1.68 µm of extra wire each. In a post-route ECO it re-routes
  only the nets the ECO routed; the nets kept from the prior routing stay as
  they were (RustROAD `docs/routing-budget.md`). `dedupe_vias` keeps one via
  per net, layer pair and point: on 24 nets, two neighbouring pins' escapes
  reached one shared top through the same via point with two Via1 variants,
  which OpenRCX could put in series; their escapes now share one via right
  after pin access. `straighten` (two passes, `turn_at_ends`) then rewrites
  same-layer staircases and zigzags (chains of three or more runs joined at
  plain corners, which carry most of the extra DEF pieces the OpenRCX
  extraction pays for) into fewer-bend paths of at most their length,
  without touching a via, where the router's clearance probe, the wide-metal
  spacing, the same-net contact rule, the same-net rule check and the
  connectivity check accept them (`turn_at_ends` lets a rewritten chain
  leave a junction along the other axis). Its optional bend-priced re-route
  stays off: it cost 25 to 31 s more per `be_route` for about 1 % fewer
  pieces (RustROAD `docs/routing-budget.md`, "Coincident same-net vias" and
  "Post-route topology cleanup").
- **Repair margins.** `target_fanout` 9 against the SDC limit of 10
  (`native_ecos.py` admits 2 to 9), `drv_margin` 0.15, `hold_drv_margin` 0.1.
- **Frontend STA and ECO helpers.** Every `rusteda import` of the frontend
  shares one compiled-Liberty cache (`--lib-cache`, `frontend/lib-cache`; the
  imported workspaces are the same either way), `ruststa run` analyses the TT
  and SS corners at once with one worker thread per corner
  (`--concurrent-corners`; the same tables), and `native_ecos.py` reads the
  run's digest cache (`--digest-cache`, `frontend/sha256-cache.json`) so that a
  pinned input outside the run tree is hashed once per file version; the
  frontend's validate step hashes every cached entry again. The Python helpers
  memoize per-cell pin views and per-port labels. On the 2026-11-02 placement,
  in eight interleaved frontend-only runs (load 0.9 to 1.8), the receipt's
  frontend STA/ECO stage took a median 34.88 s (40.72 s CPU) against 53.51 s
  (57.56 s CPU) before; the frontend outputs differed only in provenance
  fields (argument lists, helper hashes, timings), not in netlists, timing
  tables or ECO plans.
- **Frontend helpers and schedule.** Each ECO round is one helper process
  (`native_frontend_inputs.py bundle --eco-workspace`): after the bundle, the
  ECO stage of `native_ecos.py` runs on the documents and netlist graph the
  bundle already read (bundle, plan, netlist, seed, weights and receipt as
  from two processes, but for the receipt's elapsed time and peak RSS). The
  five bundle steps are part of their ECO steps (114 producer steps instead of
  119 in the host composition), and an ECO step has the 360 s deadline of the
  two steps it replaces. The helpers hash pinned inputs and run-tree files on
  up to four threads (every file is still read in full; the flow digest cache
  is merged under a lock), `estimate_spef.py` compiles its DEF patterns once,
  escapes each name once and runs Prim's tree without generator scans
  (byte-identical SPEF), and the producer wakes at a child's exit (a Linux
  pidfd) instead of at its polling tick of up to 50 ms. These changes apply to
  every allocation. Two more need a four-CPU allocation (`threads: 4`), which
  only the host adaptation admits (`native_frontend.py` accepts 2 or 16): the
  six `ruststa run` steps take all four CPUs (`--threads 4`; the timing tables
  are the same), and the prefix is one producer parallel group
  (`frontend_parallel_group`: every step but validate, which runs after it) in
  which each step waits only for the steps whose files and workspaces it uses
  (`recipe`). `tests/test_frontend_parallel_group.py` derives those files and
  workspaces from the step arguments and the helpers' file conventions on its
  own and checks that any two steps that may run together leave alone what the
  other writes (the ECO helpers read an STA workspace under a non-blocking
  shared lock and fail rather than wait). Commands, arguments (but the STA
  thread counts), outputs and the step order are those of the serial prefix.

  On the final configuration's inputs, in five interleaved repetitions per arm
  (frontend-only producer runs; LibreLane's resizer steps replayed as a black
  box from their published inputs, as in the *Repair* item below; 1-minute
  load 1.0 to 1.5), on four CPUs the receipt's frontend STA/ECO stage took a
  median 26.96 s (43.18 s CPU), against 36.89 s (43.52 s CPU) before these
  changes and 27.73 s (42.41 s CPU) with the same commands run one after
  another. The changes inside the steps (four-thread STA runs, one-process ECO
  rounds, threaded hashing, the estimator, exit-woken waits) give about 9.2 s
  of the stage and the dependency graph about 0.8 s. The graph saves more
  outside this stage (placement exports run side by side, frontend helpers
  beside synthesis and placement steps): the producer reached the end of the
  frontend in 55.2 s instead of 60.1 s (68.9 s before). On four CPUs the CPU
  time is unchanged: the gain is wall time on CPUs that were idle, and it
  shrinks on a busy host. The stage is still 1.19x LibreLane's two repair
  steps before global routing (32 + 37: 22.62 s, 23.14 s CPU; no repetition
  below 1.0x; 1.63x before these changes) and 0.49x its four repair steps
  (55.16 s); the native side of that ratio leaves out the repair after routing
  (`be_postroute`, 5.3 to 8.2 s in the complete runs), with which it is about
  0.6x. Both follow the stage table's grouping, in which the native stage also
  holds all six pre-route RustSTA runs with their imports and reports, while
  LibreLane's pre-route STA steps are in its STA row. More concurrency cannot
  close the gap: started as early as the graph allows on unlimited CPUs, the
  serial runs' step times give a stage of 25.8 s (27.7 s serial), because the

## Optional concurrent signoff

Set `parallel_signoff: true` in a new `rusteda.native-backend-inputs.v1`
configuration to emit the explicit B4 dependency group. Existing configurations
remain serial. The sixteen-core frontend allocation supplies three disjoint
two-core lanes: `be_main`, `be_antenna` followed by `be_lvs`, and `be_openrcx`
followed by `be_timing`. Input templates render only after their dependencies;
the group completes before macro/logic checks and qualification. Tool arguments,
two-thread limits, foundry decks, constraints and qualification gates are retained.

Admission sums each live command's memory reservation under a 7168 MiB group
cap, within the existing hard 8192 MiB worker cgroup. The maximum simultaneous
reservations are 2304 + 2560 + 1024 = 5888 MiB; the measured run16 estimate is
about 4.5 GiB plus the coordinator. Runs hold the root `.work/scale.lock`.
Per-command receipts record actual CPU IDs, memory reservations, dependencies
and start/wall times. Receipt order follows the manifest. All concurrent stdout
and stderr count toward the original global log limit. Failures cancel owned
process groups; the foreground worker owner retains whole-cgroup cleanup.
An internal `--stop-after` target still executes a serial prefix.

`integration/verify_ihp_parallel_signoff.py` prepares a fresh serial/parallel
replay from copied frozen physical artifacts. Pass `--execute`, six physical
CPU IDs and the absolute root scale-lock path to run the pair under bounded
scopes and GNU time. It compares complete independent reports, retaining raw
FileIDs and recording the exact path/timestamp normalization. This replay
does not replace a fresh sixteen-gate RTL-to-GDS run.

The first pair measured 690.861 s serial and 347.049 s parallel, with all five
signoff commands passing. The strict comparator retained a mismatch in KLayout's
extra internal `.lvsdb`; a fresh serial replay also differs from published run16
there. `audit_ihp_parallel_reports.py` verifies all bound raw timing reports and
complete independent report fields, retaining the unresolved database identity
explicitly. See the [B4 handoff](../../docs/handoffs/2026-10-30-parallel-signoff.md)
for raw roots, resource measurements, the unverified internal graph comparison
and source-freeze guidance.

On a four-CPU allocation (`threads: 4`, the campaign host) `parallel_signoff`
selects a two-lane group over the foundry checks only: `be_main` on CPU slots
0-1, and `be_antenna` followed by `be_lvs` on slots 2-3
(`producer.signoff_parallel_group(4)`); OpenRCX and signoff timing stay serial
before it, so `timing_accuracy` still gates the checks. Reservations are 2560
+ 2304 MiB (2560 + 2048 MiB while LVS runs) under the same 7168 MiB group cap.
`compose_native.py` sets `parallel_signoff: true` on a four-thread host unless
`host.json` sets it to false. In an interleaved replay of the three checks with
this executor on the final Ibex stream (3 serial and 3 parallel samples, order
alternated, 1-minute load 1.2 to 2.2), the median wall time fell from 687.6 s
serial to 369.8 s parallel at 825.5 vs 816.8 s CPU; the parallel samples
peaked at 2.92 GiB in the 8 GiB cgroup (the three checks alone), and every
check passed in both modes. The whole producer's cgroup peak, page cache
included, was 4,535,873,536 B and 5,400,031,232 B in two complete runs with
the group against 4,156,129,280 B in one serial run, inside the 8 GiB limit.
The checks keep their two-thread limits and decks; only their start times
change, so a receipt that
compares end-to-end times must charge LibreLane's shared checks on the same
schedule (`make_receipt.py`, `end_to_end_seconds_native_check_schedule`).
`native_flow.py` accepts a backend's parallel groups only when they equal
`signoff_parallel_group(threads)` for that backend's allocation
(`check_parallel_groups`; `tests/test_signoff_parallel_group.py`).
`integration/verify_ihp_parallel_signoff.py` replays only the six-CPU B4
group (it requires six CPUs and calls the default sixteen-CPU policy).

## Matched LibreLane reference

`reference_flow.py` runs LibreLane 3.0.17 from the same RTL, SDC, contract,
libraries and floorplan, then signs off with the same scripts as the native
flow. It adds a bounded repair loop around LibreLane's public steps:

- global-route DRV ECO rounds;
- detailed-route rounds with routed-timing ECOs (`reference_ecos.py`);
- clock-tree protection (`reference_clock_protect/`);
- antenna-diode removal and re-insertion.

`qualify_reference.py` and `strict_checks.py` bind its 13 gates. The files here
are byte-identical to the sources of the published attempt, `reference-run16f`,
except that `prepare.py` reads the latch map from
`modules/RustSys/verification/fixtures/synthetic/lec/latches-ez130.v`.

Diode removal works around a detailed-routing behaviour. In attempt e, each
round left 15–18 inserted diodes unconnected, and they reappeared every round
because their placement was kept. `reference_ecos.py` now removes them, and
`repair_antennas` re-inserts diodes where a net still needs one. It also
renames `ANTENNA_<n>` diodes to close numbering gaps, because a gap made
`repair_antennas` crash (SIGSEGV) after any deletion.

That attempt closed timing but failed foundry main DRC, so it is reported as a
non-completion with no waiver; see the [benchmark](../../docs/benchmarks.md).
The recipe generator, launcher and measurement scripts are local evidence under
`.work/ibex-closure-a2a-20261029/`, bound by hash in the
[receipt](../../docs/benchmarks/ibex-sg13g2-ez130.json). That generator patches
the pre-fix sources, so a new reference run needs a regenerated recipe.
