## 资源与操作纪律

- **重任务前先估内存。** 先跑 `free -h` 并估算峰值。交接时可用约 56 GiB，但 swap 已用 47 GiB，说明有其他会话的进程，不要杀别人的进程，比如 ngspice。
- **加内存保护。** 用 `systemd-run --user --scope -p MemoryMax=…` 或 `guard_one.py`。超过 4 GiB 的任务通过 `.work/scale.lock` 串行化。
- **CPU 分配。** 私有 rehearsal 用 E-core 24–31，不要和公开 run 的 AllowedCPUs 抢。
- **停 worker 前先核对。** 确认 request_id 和 scope Description。不要修改正在运行的 run 的输入。新实验放在独立目录，使用冻结的二进制。
- **pgrep 等待循环会匹配自己。** 在 until 循环里用 `pgrep -f` 会匹配到循环自己的命令行，永远不会退出。改用 DONE 标记文件。
- **producer 校验 CPU 亲和性。** 它要求 manifest 的 `scope.cpu_affinity` 与进程亲和性一致。私有 rehearsal 只在自己的副本里改这个字段，并写一个 `PRIVATE_AFFINITY_EDIT.txt` 说明。
- **其他约定。** Matter 插座不要 toggle。Chromium agent 不加 `--no-sandbox`。浏览器此前拒绝过本地报告，不要绕过。
