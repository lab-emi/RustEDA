**本轮实现了什么**

- `crates/rustroad-core/src/routing.rs`：提高工作量校验硬上限，并加入可选分级 `scouts` 和 eager repair 配置，旧配置省略时保留原行为。代码上限为 expansions `1<<40`、单次搜索 500M、comparisons `1<<50`；内存保护仍在。
- 同目录 `troute.rs`：ripup 校验上限提高到 10,000、repair rounds 到 10M；新增有界 `eager_hard_repair`。一次主修复拆掉最多 16 条受影响网后，先移除这些旧路线，再逐网做不拆第三方线路的 hard reconnect；失败者进入正常队列。没有递归、无界 victim 子集搜索或保留旧路线副本；临时状态在错误时也要恢复。
- `route_owner_repair.rs`：采用配置中的各级搜索预算，避免外层预算变大而内部仍被很小的固定 scout 上限截断。
- `P/budget-only03.patch`、`P/eager-only.patch`、`P/eager-multi-only.patch` 分别保存预算、单 victim、多个 victim 的窄范围增量；完整继承实现以 source05 为准。
- 根仓库 `integration/ibex_sg13g2_ez130/final_density.py`：对最终 DEF 流式计数，整数 DBU 面积，计入功能/CTS/ECO/tap 单元，仅显式配置的 filler/decap 另报；分母为 core 减真实 SRAM halo 区域，并另报宏计入后的 core 利用率。需要实际最终 DEF/GDS 与合格 placement，不能拿预布线数据通过。
- `qualify_native.py` 的 `placed_macros` 在 `END COMPONENTS` 停止扫描，修复其继续读后续超长 PG net 行而触发 64 KiB 行上限的问题。
- run05 实际使用的是 `P/run05/helpers/` 冻结 helpers：来自 `P/native_flow_final_density.py`、`P/qualify_native_final_density.py` 的 v2 overlay，以及固定的 density checker/policy。不要假设根目录通用 helper 与它们字节相同；修改后必须重新冻结全部哈希和 contract 引用。
