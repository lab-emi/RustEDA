## Native blockers, with independent controls

1. The unified flow accepts SKY130 and GF180 only; `--pdk ihp` is rejected.
2. The locked RustSys binary rejects the original SRAM Liberty range syntax
   `pin(A_ADDR[9:0])`, with S0500 at line 198.
3. An empty SRAM declaration is not an acceptable substitute: it produces S0213,
   treats outputs as 0, and emits **no SRAM instances despite exit status 0**.
   The reusable macro checker rejects this. An independent Icarus simulation with
   the original EZ130 model fails its first memory readback (`0` vs `cafef00d`).
4. RustROAD rejects the original SRAM obstruction `LAYER Metal2 SPACING 0.21`.
   Do not remove the spacing rule to force an import. Its current selected-site /
   single-height-cell constraints are also incompatible with fixed SRAM blocks.

The files `native-failures.json`, `native-tools.json` and their referenced raw logs
bind these findings to actual binaries. The current source was inspected only to
identify the further site/height limitation; that is distinct from an executed gate.

## Reference flow and lessons

The converted RTL and the LibreLane mapped netlist pass the same vendor-model
functional test: bank isolation, boundary addresses, byte masks, and execution
of load/add/store instructions. This is not full ISA validation or formal equivalence.
The 190 signal pins of the SRAM match between Verilog and LEF; GDS views exist.
The GDS includes a small lower-edge overhang, so the declared physical halo matters.

SRAM supply pins are `VDD!`, `VDDARRAY!`, and `VSS!`, all on Metal4. A logical
power hook alone is insufficient. Macro-local Metal5 collection straps connected
to global TopMetal1 clear the power-grid checker. Separate local upper-metal grids
were floating; their failed attempts are preserved. See the checked-in `pdn.tcl`.

`reference05` progressed through placement, CTS, global routing and antenna repair.
Before detailed route, TT estimated setup slack was +10.9446 ns and hold slack
-0.00568479 ns (one violation); these are not extracted timing or final closure.

LibreLane `-j 2` did not constrain the detailed router: DRT_THREADS was null and
64 OS threads were observed. That attempt was stopped and cannot be called a
two-core measurement. `reference06` used DRT_THREADS=2 and taskset on two physical
cores, then was stopped after an apparent log stall. Later observations found
log buffering around 16 KiB: the last flushed phase is not proof of a hang.
Standalone black-box controls entered actual routing both with and without
an explicit routing-layer reset. `reference07` is the bounded one-iteration
control. Consult `result.json` for its outcome; do not infer final completion
or a configuration bug from the earlier partial logs.

The AppImage subprocess tree can make the outer GNU-time peak incomplete when a
run is interrupted. `monitor_scope.py` additionally records cgroup memory.peak,
swap peak, sampled process VmHWM, and CPU masks. Do not replace missing resource
values with zero or present stopped/continued runs as fresh E2E timings.
